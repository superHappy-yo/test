# Supplemental A40 process replications

Three independent processes repeat the existing `shapefuse bakeoff` on A40
GPU `GPU-b356d1b0-c3da-551d-07d4-ee0a3c97bbc4`. The original `bakeoff_v4`
run used the other physical A40 recorded in its run notes. Original results
are retained without modification.

Each process uses FP16, seven MatMul+RMSNorm shapes and five attention shapes,
three warmups and ten regular iterations, and `all-gemm` calibration with
one warmup and three probe iterations. Attention retains the uncalibrated
compiled-SDPA-chain policy. Max-autotune is intentionally skipped: each run
contains 65 successful latency rows and 12 skipped rows, rather than 77
successful measurements. PyTorch is 2.5.1+cu121, CUDA 12.1, Python 3.10.12.

The startup criterion is two consecutive samples with utilization at most
5% and used device memory at most 256 MiB. During-run monitoring includes
the benchmark itself and cannot isolate unrelated processes.

`replication_manifest.json` contains exact commands, startup samples and
process return codes. Each run directory contains unedited harness CSVs,
summary JSON, the run log, and GPU monitoring samples. Timings use CUDA
events. Selected latencies copy baseline medians; compilation, calibration,
dispatch and switching costs are not included. No Nsight DRAM counters or
custom fusion kernels are measured.

GEMM probes agree with the regular two-path minimum in all 21 shape--run
comparisons. The seven-shape geometric-mean selected speedups are 1.053,
1.056 and 1.047. The compiled attention chain is slower than eager SDPA
on all 15 shape--run comparisons. These are subgraph results under this
protocol, not classifier accuracy or end-to-end inference speedups.

To repeat into a new directory, from the repository root:

```bash
python paper/jsa/scripts/run_jsa_replications.py \
  --gpu-uuid GPU-b356d1b0-c3da-551d-07d4-ee0a3c97bbc4 \
  --runs 3 --out results/jsa-replication-new
python paper/jsa/scripts/analyze_jsa_evidence.py \
  --replications results/jsa-replication-new --out results/jsa-analysis-new
```

The runner refuses to overwrite an existing output directory. Timing
ratios quoted in the manuscript are generated by the analysis script
and stored in `../jsa_reanalysis/evidence_audit.json`.
